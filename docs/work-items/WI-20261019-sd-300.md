- 现象: Inventory 里选中一个技能，Tab 到「Copy skill name」按钮按 Enter / Space（或鼠标点），技能名进了剪贴板、也显示「Skill name copied.」，但 `document.activeElement` 变成 `<body>`。键盘用户要从页面开头重新 Tab；连按两次时第二下打在 body 上，什么也不发生。闻测在 main `48e15dd3` 的 linux 包上复现（Issue #300 附截图）。
- 原因: 打包后的 `electron-security.ts` 拒绝所有权限，`navigator.clipboard.writeText` 总是 NotAllowedError，`copyTextToClipboard` 每次都走 legacy 兜底：建 textarea → `area.focus()` → `execCommand("copy")` → `area.remove()`。焦点跟着被删掉的 textarea 一起没了，没有还给原来的按钮。所以包里每次复制都丢焦点，不是偶发。
- 想改成啥: 兜底路径开始前记住 `document.activeElement`，在 `finally` 里删掉 textarea 后把焦点还回去（`focus({ preventScroll: true })`，元素还在 DOM 里才还）。复制成功、`execCommand` 返回 false、抛异常三种情况都还焦点。不改 Electron 权限，不改 live region 文案。
- 验收:
  1. 新 vitest + Testing Library 用例（`InventoryApp.test.tsx` → `keeps focus on the copy button when the legacy copy succeeds|fails after the Clipboard API is denied`）：stub `navigator.clipboard.writeText` 抛 NotAllowedError（和打包后的权限一样），先 `focus()` 按钮再激活，断言 `document.activeElement` 是「Copy skill name」按钮、不是 body，textarea 已删除；紧接着第二次激活（模拟先 Enter 再 Space）仍落在按钮上。没修之前这两条用例红，修后绿。
  2. packaged smoke（`tests/packaged-electron.smoke.mjs`，Verify 里在 xvfb 跑）加一步：选中 `packaged-project-skill`，聚焦并点击「Copy skill name」，出结果后 `document.activeElement` 的 aria-label 必须是 `Copy skill name`。没修时本地报 `activeTag: "BODY"` 红，修后绿。
  3. 本地 typecheck、lint、`npm test` 全绿；PR CI 的 Package darwin / linux / win32 + Verify 全绿（Vercel 红可忽略）。
  4. 闻测在实机包上截图：Enter 后、Space 后、鼠标点后焦点环都还在「Copy skill name」上。
